# Gate A（すり合わせ）→ Inputs for PPT Production → Gate B（ブループリント承認）

すり合わせ・材料の整理・ブループリント引き渡しの手順。デザイン・形式は同梱のスキンと PDF に固定なので、ここでは「何を言うか」だけを決める。

## Gate A: すり合わせ

ユーザーの依頼と材料から埋まる項目は埋め、埋まらない項目だけを1回でまとめて聞く。

| 項目 | 選択肢・例 | おまかせ時の既定値 |
|---|---|---|
| 聴衆と場 | 顧客の部長会、社内の役員報告 など | 材料から推定して明記 |
| 判断してほしいこと | 承認・A案かB案か・方向性の合意 など | 材料から推定して明記 |
| 提示のしかた | **発表型**（話し手が補う）／**読み物型**（PDF で送って単体で読まれる） | 送付するなら読み物型、会議で映すなら発表型 |
| 枚数 | 目安の枚数か範囲 | 7〜10枚 |
| 密度 | 簡潔／標準／密 | 標準 |
| 言語 | 日本語／英語 | 依頼の言語 |
| 根拠の範囲 | 使ってよい資料・数字・社名。出してはいけないもの | 渡された材料だけ |
| 入力の加工 | 拡張（薄い材料を補う）／圧縮（長い材料を削る）／書き直し／研ぐ（ほぼ良いものを締める）／保持 | 研ぐ |

- 「おまかせ」と言われたら、既定値で埋めた表を1行ずつ示してそのまま進む。
- 聴衆と判断事項がどうしても推定できないときは、デッキにせず1枚の論点整理で返す（slide-rules §0）。
- 発表型は slide-rules §9（ピッチデック）を適用する。読み物型は各ページが話し手なしで So what まで読めること。

**完了条件**: 全項目が「ユーザーの回答」か「既定値として明示済み」のどちらかになっている。

## Inputs for PPT Production

Gate A のあと、材料をこの形に変換してチャットに表示する（ファイル `brief.md` にも保存）。根拠が足りない主張は隠さず「必要な根拠」「未決事項」に出す。

```markdown
## Inputs for PPT Production

### 前提
- 聴衆 / 場:
- 判断してほしいこと:
- 提示のしかた: 発表型 / 読み物型
- 枚数 / 密度 / 言語:

### Core Question
<このデッキが答える問いを1文で>

### Working Thesis
<その問いへの答え・判断を1文で>

### ストーリー（論理の段）
1. <段>
2. <段>
3. <段>

### ページ単位の入力
#### P1: <仮タイトル（主張文）>
- 主張:
- なぜ重要か:
- タイトルに載せる示唆（So what）: <読み手が持ち帰る判断。下部には置かず、タイトル（2行まで）に入れる>
- proof object: <主張を証明する見せ方。references/claim-evidence.md の対応表から>
- ある根拠: <各項目に 事実／前提／推論 を付ける。claim-evidence.md の「根拠の4区分」>
- 未解決: <確認が取れていないこと。未決事項にも書く>
- 必要な根拠:
- 注意書き・出典:

### 未決事項
- <ユーザー確認か裏取りが必要なもの>
```

**完了条件**: 全ページに主張と proof object が入り、根拠の無い主張はすべて「必要な根拠」か「未決事項」に載っている。本文の全ページで、示唆がタイトルに入る文になっている（下部のまとめには逃がさない。slide-rules §4.8）。

## ブループリント（タイトル列）

Inputs をもとに slide-rules §0-1・§2 に従ってタイトル列を作る。タイトルは常体の主張文で、上から通し読みして1本のスピーチになること（§2.6）。各行に型番号と claim-evidence map の要点を付ける。

## Gate B: ブループリント承認

チャットに必ずこのブロックを表示する（ファイルパスだけで済ませない）。「何を承認しているのか」がこのブロックだけで分かることが基準。

```markdown
承認いただきたいストーリーライン:

Core Question: <1文>
Working Thesis: <1文>

| # | タイトル（主張文） | 役割 | 型 | proof object | 根拠 | 示唆がタイトルに入っている |
|---|---|---|---|---|---|---|
| 1 | ... | 表紙 | b01 | - | - | - |
| 2 | ... | 結論 | m01 | ... | あり | ○ |
| 3 | ... | 根拠 | m05 | ... | 要追加: ... | ○ |

「示唆がタイトルに入っている」が × のページは、承認に出す前にタイトルを直す。

サンプルにするページ: P<n>（理由）, P<m>（理由）

「承認」か、直したいページを教えてください。承認まで HTML は作りません。
```

**完了条件**: ユーザーが承認した。修正指示なら、ブループリントを直して再表示する。
